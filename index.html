FEP / RESPONSIBILITY & SCOPE

FEP 문제를 반복하지 않는 방법

FEP는 일반적으로 Front-End Processor라는 뜻으로 사용되지만 사업에 따라 맡는 범위가 다릅니다. 기능 경계와 업체별 책임을 먼저 합의합니다.

01 / 통화에서 확인된 세 가지 임무
  1. 공통모듈 목록, 기능, API, 버전, 변경 영향, 회귀검증 관리
  2. 개발표준 가이드 작성, 샘플 배포, 준수 여부 검증
  3. 컨테이너 환경 설치, 설정, 배포, 실행, 정상성 확인
02 / 문제 해결 프레임
현상, 범위 확인 → 이벤트 → 로그 → 설정 → 네트워크/DB 연계 → 원인 판단 → 승인된 조치 → 재검증
03 / 핵심 기술 5개
Docker: 이미지, 실행 / Kubernetes: Pod, Deployment, Service / Probe: Readiness, Liveness / API: 계약, 호환성 / 변경: 영향분석, 회귀 테스트
04 / 위성영상 도메인
수신, 반입 → 데이터 검증, 처리 → 저장, 메타데이터 → 검색/API → 분석, 서비스
STAC: 시공간 메타데이터 / COG: 영상 부분 조회 최적화. 실제 사용 기술로 확정하지 말 것.


05 / 가장 강한 답변의 구조
결론 “핵심은 ○○입니다.” → 경험 “저는 ○○을 관리했습니다.” → 실행 “투입 시 ○○부터 확인하겠습니다.”

  2. 컨테이너 업무가 응용 설치, 검증인가, 클러스터 구축인가?
  3. 정확한 언어, 프레임워크, CI/CD, 플랫폼은?
  4. 개발팀 규모, 기술결정 권한, 플랫폼 담당팀은?
  5. 수서/제주 비율, 급여, 체류비, 계약서상 30개월은?
